# 本次任务总结

## 1. 任务目标

检查 `ur10_ft300_monitor` 中 FT300 力传感器是否在采集初始状态执行清零（tare/zero）。

## 2. 根因分析

结论：当前实现**没有**在采集启动阶段进行硬件或软件初始清零。

证据：
- `scripts/ft300_reader.py` 连接时仅发送开启连续输出指令 `build_fc16_start_stream`，随后直接读帧，不含 zero/tare 指令或偏置扣除状态（见行 47-62、80-97、99-125）。
- `scripts/fusion_logger_gui.py` 的 `start_capture()` 仅清空缓存并启动线程，不做 FT 初始均值估计/偏置注入（见行 249-279）。
- 原始 CSV 首帧 FT 值明显非零，例如 `Fx=-16.25, Fy=34.42, Fz=42.62`，说明采集侧未归零。

补充：分析模块存在“离线零点修正”，但这不是采集初始清零：
- `analysis/metrics_utils.py` 的 `compute_baseline()/apply_ft_correction()` 在分析阶段基于 Label 段或前 5% 样本扣基线（见行 186-227）。

## 8. 剩余问题

- 缺少“采集启动自动清零”机制。

## 9. 下一步建议

1. 在 `FT300Reader` 增加 `tare_mode`（`none`/`software`）参数，默认 `software`。
2. 采集启动后先抓取 N 帧静止数据（如 100 帧），计算 6 轴偏置并在实时输出中扣除。
3. GUI 增加“清零”按钮，支持采集中二次归零。
4. 在 `metadata.txt` 写入 `ft_zero_offset` 与 `zero_sample_count`。

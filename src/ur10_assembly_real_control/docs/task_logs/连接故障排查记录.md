# UR10 + ROS2 + WSL2 External Control 连接故障排查记录

## 问题现象

UR10 CB3 示教器运行 `External Control` 程序时出现：

```text
Receive program failed
The connection to the remote PC at 10.160.9.100:50002 could not be established.
Reason: Connection refused
```

ROS2 侧表现：

* `ur_ros2_control_node` 正常启动
* RTDE 通信正常
* Dashboard 正常连接
* MoveIt2 可以规划
* 但真实机械臂无法执行轨迹

---

# 一、最终根因

真正原因：

```text
Windows 本机的 wslrelay.exe 占用了 127.0.0.1:50002
导致 netsh portproxy 无法监听 10.160.9.100:50002
```

因此：

```text
UR10 → 10.160.9.100:50002
```

连接时：

```text
Connection refused
```

---

# 二、关键诊断过程

---

## 1. ROS2 Driver 实际已经正常

WSL2 中：

```bash
ss -lntp | grep -E '50001|50002|50003|50004'
```

输出：

```text
LISTEN 0 1 0.0.0.0:50001
LISTEN 0 1 0.0.0.0:50002
LISTEN 0 1 0.0.0.0:50003
LISTEN 0 1 0.0.0.0:50004
```

说明：

```text
ur_ros2_control 正在监听 reverse interface
```

---

## 2. Windows PortProxy 配置存在

```powershell
netsh interface portproxy show all
```

输出：

```text
10.160.9.100 50001 -> 172.17.201.231 50001
10.160.9.100 50002 -> 172.17.201.231 50002
10.160.9.100 50003 -> 172.17.201.231 50003
10.160.9.100 50004 -> 172.17.201.231 50004
```

说明：

```text
配置本身没问题
```

---

## 3. 真正关键测试

Windows：

```powershell
Test-NetConnection 10.160.9.100 -Port 50002
```

结果：

```text
TcpTestSucceeded : False
```

这一步说明：

```text
Windows 根本没成功监听 10.160.9.100:50002
```

---

## 4. netstat 发现端口被占用

```powershell
netstat -ano | findstr ":50002"
```

输出：

```text
TCP 127.0.0.1:50002 LISTENING 12580
```

说明：

```text
50002 已被其他进程占用
```

---

## 5. 查出占用进程

```powershell
tasklist /fi "PID eq 12580"
```

输出：

```text
wslrelay.exe
```

---

# 三、解决方法

---

## 1. 关闭占用进程

```powershell
taskkill /PID 12580 /F
```

---

## 2. 删除旧 portproxy

```powershell
netsh interface portproxy delete v4tov4 listenaddress=10.160.9.100 listenport=50002
```

---

## 3. 重新建立 portproxy

```powershell
netsh interface portproxy add v4tov4 `
  listenaddress=10.160.9.100 `
  listenport=50002 `
  connectaddress=172.17.201.231 `
  connectport=50002
```

---

## 4. 再次检查监听

```powershell
netstat -ano | findstr ":50002"
```

正确结果：

```text
TCP 10.160.9.100:50002 LISTENING
```

---

## 5. 再次测试 TCP

```powershell
Test-NetConnection 10.160.9.100 -Port 50002
```

正确结果：

```text
TcpTestSucceeded : True
```

---

# 四、最终结果

CB3 示教器：

```text
External Control successfully connected
```

真实机械臂可以：

* 接收 MoveIt2 轨迹
* Execute 正常
* ROS2 控制恢复

---

# 五、经验总结（非常重要）

## 1. `portproxy show all` 不代表真正可用

即使：

```powershell
netsh interface portproxy show all
```

存在配置，

也必须检查：

```powershell
netstat -ano | findstr ":50002"
```

以及：

```powershell
Test-NetConnection
```

---

## 2. 最关键的诊断命令

### Windows

```powershell
Test-NetConnection 10.160.9.100 -Port 50002
```

这是判断：

```text
UR10 能否真正连上 Windows
```

最关键的一步。

---

## 3. WSL2 / mirrored networking 容易抢占端口

某些情况下：

```text
wslrelay.exe
```

会自动占用：

```text
127.0.0.1:50002
```

从而导致：

```text
portproxy 无法监听真实网卡
```

---

## 4. 排查优先级

以后按这个顺序查：

### Step 1

WSL 是否监听：

```bash
ss -lntp
```

### Step 2

Windows 是否真正监听：

```powershell
netstat -ano
```

### Step 3

TCP 是否真正连通：

```powershell
Test-NetConnection
```

### Step 4

再看示教器 External Control

不要一开始就怀疑 ROS2 driver。

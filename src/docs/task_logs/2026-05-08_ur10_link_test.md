新建 ROS2 Humble Python 功能包 `ur10_link_test`，用于 UR10/CB3 联通测试和基础原因分析。工具只做只读网络诊断，不控制机械臂，不调用 `RTDEControlInterface`，不写 RTDE input recipe，不占用 `speed_slider_mask`。

## 2. 根因分析

本次实测结果显示：

- `10.160.9.21` 可 ping 通。
- UR 控制器端口 `29999/30001/30002/30003/30004` 均可建立 TCP 连接，说明上位机到机器人基础网络链路可达。
- 本机未监听 `:50002`，所以示教器 External Control 连接 `10.160.9.100:50002 refused` 是合理现象：当前没有可接收 External Control 脚本连接的 driver/script sender 监听端口。
- 当前环境为 WSL，存在 WSL2 NAT 风险；即使 WSL 内部监听端口，也不等于 Windows 宿主机对机器人可达。
- 运行后 `ss -tnp | grep ':30004'` 无输出，说明本诊断节点没有长期占用 RTDE 端口。
- 运行后仍存在 `dashboard_client`、`robot_state_helper`、`urscript_interface` 到机器人 `29999/30001/30002` 的连接，这是已有驱动相关进程，不是本诊断节点残留。

## 5. 核心实现逻辑

节点使用 `rclpy` 参数读取默认机器人 IP、主机 IP、External Control 端口和报告路径。网络探测只使用 Python 标准库：

- `socket.connect_ex()` 执行 TCP 端口连通性测试，设置 2 秒 timeout，连接后立即关闭。
- `subprocess.run(..., timeout=...)` 执行 `ping`、`ss -lntp`、`ss -tnp`。
- `platform.platform()` 和 `/proc/version` 判断 WSL 环境。
- `json` 和 `datetime` 生成结构化报告。

分析规则：

- 如果 `50002` 未监听，External Control refused 优先解释为 driver/script sender 未监听。
- 如果 `29999` 和 `30004` 可连接且已观察到 `speed_slider_mask` 报错，说明网络基本通，优先排查 RTDE 写资源占用。
- 如果本机无 `30004` 连接但仍报 `speed_slider_mask`，建议重启 UR 控制柜并排查其他电脑、URCap、Fieldbus/PLC。
- 如果 WSL 环境存在，提示 Windows 端口转发或 WSL2 mirrored networking 风险。

## 8. 剩余问题

- 本机当前没有监听 `50002`，External Control 从示教器连接被拒绝仍会发生。
- 当前环境为 WSL，机器人连接 WSL 内部服务可能受 NAT 影响。
- 若 `speed_slider_mask` 报错继续出现，而本机无 `30004` 连接，应优先重启 UR 控制柜，并检查其他电脑、URCap、Fieldbus/PLC 是否占用 RTDE 输入寄存器。
- 仍存在已有驱动相关进程连接 `29999/30001/30002`，必要时应明确停止旧的 `ur_robot_driver` 相关进程后再重新联调。

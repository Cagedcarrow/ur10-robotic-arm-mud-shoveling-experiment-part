# 泥重量投影原理说明

## 1. 为什么不能直接用总力模长算重量

旧版脚本直接使用：

```text
|F| = sqrt(Fx^2 + Fy^2 + Fz^2)
```

这个值会把以下因素全部混在一起：

- 泥的真实重力
- 铲泥过程中受到的泥浆阻力
- 机械臂姿态变化导致的力传感器坐标投影变化

因此，当最早的稳定段仍处在高阻力阶段时，`|F|` 可能比最终出泥后的称重段还大，进而得到错误的负重量。

## 2. 本次模型坐标链

参考模型文件：

```text
/root/ur10_ws/src/ur_base_xarco_model/assembly_xacro/assembly/assembly.urdf.xacro
```

本次分析实际使用的关键固定关节是：

- `ur10-sensor_shovel`
  - `ur10_wrist_3 -> sensor_shovel`
- `sensor_shovel_tcp`
  - `sensor_shovel -> sensor_shovel_shovel_tcp`

其中：

- `sensor_shovel` 视为 FT300 力的测量坐标系
- `sensor_shovel_shovel_tcp` 视为 UR 返回姿态对应的 shovel TCP 参考系

## 3. 静态旋转关系

模型中 `sensor_shovel -> sensor_shovel_shovel_tcp` 的固定旋转为：

```text
rpy = (-1.5708, 1.5708, -0.61087)
```

这意味着：

- FT300 测到的三轴力不是天然对齐世界重力轴的
- 需要先把 TCP 姿态转换到传感器姿态
- 再把传感器力投影到机器人基坐标系

## 4. 计算流程

对每个样本，分析脚本执行以下步骤：

1. 由 `Act_RX / Act_RY / Act_RZ` 构造 TCP 相对基坐标系的旋转矩阵 `R_base_tcp`
2. 由模型固定关节得到 `R_tcp_sensor`
3. 计算传感器姿态：

```text
R_base_sensor = R_base_tcp * R_tcp_sensor
```

4. 将传感器力变换到机器人基坐标系：

```text
F_base = R_base_sensor * F_sensor
```

5. 默认取 `F_base_z` 作为重力方向上的主分析量

## 5. 为什么参考段要改成“最终前一稳态”

你的实验语义不是“最早静止=0 g”，而是：

- 开始阶段会经过接触泥浆和高阻力区域
- 真正适合做 `0 g` 参考的，是最终称重前、姿态接近且阻力较弱的那段稳定状态

因此新脚本默认规则改为：

- 最后一个长稳态段：最终称重点
- 最终称重点前一个长稳态段：`0 g` 参考段

这样可以避开最早的高阻力稳态，避免把阻力误当成空载基准。

## 6. 这份数据为什么会接近 230 g

针对 `data/2026-05-01_19-57-41/ur10_ft300_realtime_data.csv`：

- 旧算法把最早高阻力稳态当基准，所以得到明显错误的负值
- 新算法改用最终前一稳态作为 `0 g` 参考
- 再使用模型修正后的 `F_base_z` 进行力差换算

这会把结果拉回到两百多克量级，与现场记录的 `+230 g` 基本一致。

## 7. 限制条件

当前方法已经比总力模长更合理，但仍有边界条件：

- 前提是 `Act_RX/RY/RZ` 的姿态语义与默认 TCP 帧一致
- 若实际 UR 控制器使用的不是 `sensor_shovel_shovel_tcp`，需要切换 TCP 帧参数
- 若参考段仍残留明显流体阻力，重量会偏小或偏大
- 若力传感器零点漂移明显，仍需在采集层补零或加标定步骤

## 8. 适合后续继续增强的方向

- 自动比较多个前置稳态段，选择更可信的 `0 g` 参考
- 接入视频关键帧，联动确认“出泥完成”的时间点
- 增加力传感器零点校准或每次实验前的空载标定
